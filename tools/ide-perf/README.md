# ide-perf — сравнение производительности IDE

Скрипт запускает IDE на проекте несколько раз и снимает метрики:
- **старт**;
- **сканирование и индексацию**;
- **время от запуска до smart mode**;
- **число ERROR/WARN в логах**;
- **heap при выходе**.

По результатам он строит HTML-отчёт с графиками. Результаты нескольких прогонов (разные версии или форки, разные машины) накладываются на одни графики.

Нужен только Python 3.9+, без зависимостей. IDE должна быть с бандл-плагином **Performance Testing**. Он есть в IntelliJ IDEA, в сборках из этого репозитория и в Android Studio.

## Запуск

```bash
# прогон на первой IDE
python3 tools/ide-perf/ide_perf.py run --ide "/Applications/IntelliJ IDEA OSS.app" \
  --project ~/work/my-project --label "OSS 2026.2.3" -n 5 --out perf/oss.json

# прогон на второй IDE (можно на другой машине, потом скопировать json)
python3 tools/ide-perf/ide_perf.py run --ide "/Applications/SD-OpenIDE.app" \
  --project ~/work/my-project --label "SD-OpenIDE" -n 5 --out perf/sd.json

# сводный отчёт: первый json — база, для остальных считается Δ%
python3 tools/ide-perf/ide_perf.py report perf/oss.json perf/sd.json -o perf/report.html
```

`report` принимает и один json (отчёт по одной IDE), и больше двух.

## Как устроена итерация

1. Для итерации создаются пустые `config/system/log/plugins` в `perf/<имя json>/iter-N/`. Это холодный старт: индексы строятся с нуля, пользовательские плагины не грузятся.
2. IDE запускается с проектом. Свойства передаются через `IJ_JAVA_OPTIONS`, его дописывает нативный лаунчер. Скрипт плагина `%waitForSmart` + `%exitApp` дожидается конца индексации и закрывает IDE.
3. Метрики берутся из файлов, которые пишет сама IDE:
   - `startup.json` (`idea.log.perf.stats.file`) — общий старт и фазы;
   - `log/indexing-diagnostic/*/diagnostic-*.json` — сканирование и индексация;
   - `log/idea*.log` — ERROR/WARN;
   - `exit.json` (`idea.log.exit.metrics.file`) — heap.
4. Каталог `system` (индексы) удаляется, логи остаются для разбора. Флаг `--keep-caches` оставляет и `system`.

## Полезно знать

- Для Ultimate или лицензируемого форка подготовьте конфиг с активированной лицензией и передайте его через `--config-from <dir>`. Он копируется в каждую итерацию.
- Если IDE не закрылась за `--timeout` (по умолчанию 1800 с), итерация получит статус `timeout`, а метрики всё равно соберутся. Обычно причина — модальный диалог. Посмотреть, какой именно, можно через `jstack <pid>`.
- Первая итерация часто медленнее из-за холодного дискового кэша ОС. Поэтому в отчёте медианы; берите `-n 5` и больше.
- Сравнивать имеет смысл на одной машине, одном проекте и без фоновой нагрузки.
- Для графиков отчёт подгружает Chart.js с cdnjs, так что при просмотре нужен интернет.

Самотест парсеров и отчёта: `python3 tools/ide-perf/test_ide_perf.py`.
