## Context

- Во вкладках Blackbird простой Escape до blackbird не доходит. Ctrl+Esc доходит: JediTerm не поддерживает протокол kitty и modifyOtherKeys, поэтому на Ctrl+Esc отправляет обычный ESC, и blackbird срабатывает по своей привязке `escape`. Отличить Ctrl+Esc от Esc blackbird в IDE не может, поэтому привязки клавиш менять нельзя.
- Подсказка в строке состояния промпта зашита в коде как `esc`, в файле `packages/tui/src/component/prompt/index.tsx` (v1 около строки 1587, v2 около строки 140).
- Как blackbird принимает настройки интерфейса от внешнего процесса, не трогая файлы пользователя:
  - v1: `BLACKBIRD_TUI_CONFIG` — путь к файлу. Он накладывается поверх глобального `tui.json`, но под `tui.json` проекта и каталога конфигурации.
  - v2: `BLACKBIRD_CLI_CONFIG_CONTENT` — JSON. Он сливается поверх `~/.config/blackbird/cli.json` с глубоким слиянием.

  Обе переменные — это `OPENCODE_*`, которые выставляет `blackbird-env.ts`.

## Goals / Non-Goals

**Goals:**
- По умолчанию в IDE blackbird подсказывает «ctrl+esc interrupt».
- В консольном blackbird без настроек ничего не меняется.
- Текст подсказки задаётся в настройках плагина для каждой версии.

**Non-Goals:**
- Изменение привязок клавиш и логики прерывания в blackbird.
- Починка передачи простого Escape во вкладках Blackbird.
- Изменения в плагине OpenCode.

## Decisions

1. **Отдельный параметр отображения `interrupt_hint`, а не переназначение привязки.** Параметр меняет только текст и не затрагивает то, на какую клавишу реагирует blackbird. Переназначение `session.interrupt` отклонено:
   - в IDE Ctrl+Esc приходит как обычный ESC, и привязка `ctrl+escape` в IDE никогда бы не совпала;
   - любая ошибка в настройке ломала бы само прерывание, а не только подсказку.
2. **Параметр в конфигурации интерфейса.** В v1 это `tui.json`, в v2 — `cli.json`. Это строка, по умолчанию `esc`. Пустая строка означает значение по умолчанию.
3. **Плагин передаёт параметр переменной окружения.**
   - v1: плагин пишет `{"interrupt_hint":"<текст>"}` в файл в системном каталоге IDE и передаёт путь в `BLACKBIRD_TUI_CONFIG`. Файл перезаписывается, только если его содержимое изменилось.
   - v2: плагин передаёт `BLACKBIRD_CLI_CONFIG_CONTENT={"interrupt_hint":"<текст>"}`.

   Линию определяет мажорная версия, как для `--standalone`. Переменную, уже заданную в окружении, плагин не трогает. Записывать параметр в файлы пользователя отклонено: так поменялся бы и консольный blackbird.
4. **Поле в форме настроек.** Текстовое поле «Interrupt key hint» рядом с режимом совместимости. Оно хранится как `sd.blackbird.interruptHint.<версия>`, по умолчанию `ctrl+esc`. Пустое поле значит «не передавать».
5. **Терминалы IDE.** `BlackbirdPathCustomizer` добавляет ту же переменную для версии по умолчанию.

## Risks / Trade-offs

- [Старый blackbird без поддержки `interrupt_hint`] → v1 и v2 должны пропускать неизвестный ключ. Иначе плагин сломает запуск старых бинарников. В задаче для blackbird это требование приёмки. Сам плагин обновит бинарники только вместе с поддержкой параметра.
- [`interrupt_hint` в `tui.json` проекта или каталога конфигурации в v1 перекрывает значение плагина] → Это явная настройка пользователя.
- [В v2 переменная плагина перекрывает `interrupt_hint` из `cli.json`] → Чтобы показывать своё значение, пользователь задаёт его в поле плагина.
- [Простой Escape во вкладках по-прежнему не работает] → Это отдельная задача.
