## Context

Плагин OpenCode for IntelliJ 0.2.0 (`plugins-external/opencode/`) — отдельный Gradle-проект. Его состав:

- **Панель с вкладками-сессиями.** Каждая вкладка — локальный shell, который запускает `opencode`. Справа от «+» есть стрелка выбора версии.
- **`opencode` в `PATH` терминалов** — через `OpenCodePathCustomizer`.
- **Escape** передаётся в процесс opencode собственным dispatcher'ом.
- **Settings | Tools | OpenCode.** Здесь задаются версия по умолчанию и для каждой версии каталог конфигурации (`OPENCODE_CONFIG_DIR`). Модели `model` и `small_model` пишутся прямо в `opencode.json[c]`, а сам файл показывается в настройках.
- **Пункт настроек в меню «⋮» панели.**
- **Сборка zip под каждую ОС.** `package_plugin.py` докладывает бинарники из GitHub-релизов и проверяет их по SHA-256.

Что известно о blackbird (ветки `blackbird/v1` и `blackbird/v2`, `BLACKBIRD.md`, релизы `v1.19.5.2` и `v2.2.5.2`):

- **Имена.**
  - Бинарник — `blackbird`.
  - Конфигурация — `~/.config/blackbird` и `blackbird.json[c]`.
  - Переменная `BLACKBIRD_X` копируется в `OPENCODE_X` при старте (`blackbird-env.ts`), поэтому `BLACKBIRD_CONFIG_DIR` работает как `OPENCODE_CONFIG_DIR`.
- **`--opencode-compatible[=<dir>]`.**
  - Флаг убирается из argv и выставляет `BLACKBIRD_OPENCODE_COMPATIBLE=1`. С `=<dir>` он ещё задаёт `OPENCODE_CONFIG_DIR=<dir>` и этим перекрывает `BLACKBIRD_CONFIG_DIR`.
  - Переменная `BLACKBIRD_OPENCODE_COMPATIBLE=1` без флага включает тот же режим (`brand.ts`).
  - В этом режиме blackbird работает на файлах, базе, сервисе и провайдерах opencode.
- **`--opencode-import [<path>]`.**
  - Это однократная команда: выполняет импорт, печатает отчёт («Скопировано / Бэкап / Пропущено») и завершается с кодом 0 или 1.
  - Без пути она копирует XDG-каталоги `config`, `data` и `state` opencode в каталоги blackbird. С путём импортирует файл или каталог рядом с источником.
  - Базу сессий она пропускает, если базу писал opencode более новой мажорной версии. Поэтому результат зависит от версии blackbird, которая выполняет импорт.
- **Обе линии** поддерживают оба флага.
- **Фоновый сервис.** Линия 2.x, как и opencode 2.x, запускает сессии в общем фоновом сервисе, который не видит переменные окружения вкладки. Обходится это так же: `--standalone`.
- **Релизы.** Архивы называются `blackbird-v<версия>-{darwin,linux}-{arm64,x64}.tar.gz` и `blackbird-v<версия>-windows-{arm64,x64}.zip`. SHA-256 берётся из `SHA256SUMS` релиза.

## Goals / Non-Goals

**Goals:**
- Плагин blackbird, повторяющий плагин opencode по поведению и коду.
- Режим совместимости и импорт из opencode в настройках, отдельно для каждой версии.

**Non-Goals:**
- Общая библиотека для двух плагинов.
- Изменения в SD-OpenIDE: место кнопки в раскладке по умолчанию и `JBTerminalWidget.isTerminalToolWindow` для id `Blackbird`. Панель встаёт внизу по умолчанию платформы, Escape обрабатывает сам плагин.
- Публикация в GitHub-релиз (только по отдельной просьбе).
- Перевод текстов UI.

## Decisions

### D1. Копия плагина opencode с заменой имён
`plugins-external/opencode/` копируется в `plugins-external/blackbird/`. Затем:

- `opencode` заменяется на `blackbird` в пакете, id плагина (`io.sdopenide.blackbird`), id панели (`Blackbird`), id настроек (`sd.blackbird`), ключах `PropertiesComponent` (`sd.blackbird.*`), переменной вкладки (`SD_BLACKBIRD_BIN_DIR`), `rootProject.name` и названиях классов (`Blackbird…`).
- Иконки делаются из иконок opencode, с другой буквой или цветом.
- `Jsonc.kt` и его тест копируются без изменений.
- Версия плагина — `0.1.0`.

*Альтернатива:* один плагин на оба агента или общий модуль. Это больше кода, и пользователь просил именно копию.

### D2. Бинарники из релизов blackbird
В `package_plugin.py` меняются:

- **Версии:** `DEFAULT_VERSION = "1.19.5.2"` и вторая `2.2.5.2` (как 1.x и 2.x в плагине opencode).
- **Адрес релиза:** `https://github.com/MartynovAleksey/blackbird/releases/download/v<версия>/blackbird-v<версия>-<os>.<ext>`.
- **Соответствие `<os>` плагина:** `macos-*` → `darwin-*`.
- **SHA-256:** из `SHA256SUMS`.
- **Пути в zip:** бинарник ищется в архиве по имени `blackbird[.exe]` и кладётся в `bin/blackbird` или `bin/versions/<версия>/blackbird`. Файл `bin/version.txt` содержит версию по умолчанию.

Мажорная версия для `--standalone` берётся из первого числа (`2.2.5.2` → 2).

### D3. Конфигурация версии: обычный режим и режим совместимости
Для каждой версии хранятся:

- `sd.blackbird.configDir.<v>`: каталог конфигурации blackbird;
- `sd.blackbird.compat.<v>`: флажок совместимости, по умолчанию включён (хранится только выключенное значение);
- `sd.blackbird.opencodeDir.<v>`: каталог конфигурации opencode, необязательный.

Что получает вкладка версии:

| Режим | Переменные окружения | Команда |
|---|---|---|
| Обычный | `BLACKBIRD_CONFIG_DIR`, если каталог задан | `blackbird` |
| Совместимость без каталога | `BLACKBIRD_CONFIG_DIR` не передаётся (иначе он стал бы `OPENCODE_CONFIG_DIR`) | `blackbird --opencode-compatible` |
| Совместимость с каталогом | `BLACKBIRD_CONFIG_DIR=<каталог opencode>` | `blackbird --opencode-compatible` |

Каталог opencode передаётся переменной, а не как `--opencode-compatible=<dir>`. `blackbird-env.ts` копирует `BLACKBIRD_CONFIG_DIR` в `OPENCODE_CONFIG_DIR`, то есть делает то же, что флаг с `=<dir>`. Зато путь не нужно экранировать для zsh, bash, fish и PowerShell, а вкладки и терминалы настраиваются одинаково.

К команде добавляется ` --standalone`, если мажорная версия ≥ 2 и задан хоть какой-то каталог: blackbird или opencode.

В терминалах IDE флаг передать нельзя, поэтому `BlackbirdPathCustomizer` для версии по умолчанию выставляет те же переменные. В режиме совместимости это `BLACKBIRD_OPENCODE_COMPATIBLE=1` и, если каталог задан, `BLACKBIRD_CONFIG_DIR=<dir>`. Флаг сам кладёт каталог в `OPENCODE_CONFIG_DIR`, а `BLACKBIRD_CONFIG_DIR` попадает туда же через `blackbird-env.ts`. Как и в плагине opencode, переменная не перезаписывается, если уже задана.

Модели и просмотр файла в настройках относятся к активному каталогу:

| Режим | Каталог | Файл (первый существующий) |
|---|---|---|
| Обычный | Каталог blackbird или `$XDG_CONFIG_HOME/blackbird` | `blackbird.jsonc`, `blackbird.json`, `config.json` |
| Совместимость | Каталог opencode или `$XDG_CONFIG_HOME/opencode` | `opencode.jsonc`, `opencode.json`, `config.json` |

Пока режим совместимости включён, поле каталога blackbird недоступно, а поле каталога opencode доступно.

### D4. Импорт как отдельный процесс с отчётом
В настройках есть группа «Import from opencode». В ней:

- **поле «opencode path»** — необязательное, с выбором файла или каталога; живёт, пока открыты настройки, и не сохраняется;
- **кнопка «Import from opencode»** — для версии, выбранной в «Version».

Кнопка запускает `<бинарник версии> --opencode-import [<path>]`:

- через `GeneralCommandLine` и `CapturingProcessHandler`, под модальным прогрессом;
- рабочий каталог — каталог проекта, чтобы относительные пути и проектные `.opencode` работали так же, как в терминале;
- окружение — переменные IDE без настроек вкладки.

Код 0 — информационное окно с выводом, иначе — окно ошибки с stderr. После импорта настройки перечитывают показанный файл: импорт мог создать `blackbird.jsonc`.

*Альтернатива:* запуск во вкладке панели. Но настройки модальны: вкладка оказалась бы под диалогом, а отчёт — вне настроек.

## Risks / Trade-offs

- [Глобальный импорт пишет в XDG-каталоги blackbird, а не в каталог конфигурации версии] → В подсказке к полю сказано: чтобы импортировать в свой каталог, укажите путь, а результат появится рядом с источником (поведение blackbird).
- [Импорт перезаписывает файлы blackbird] → blackbird сохраняет каждый перезаписанный файл в `.bak`, поэтому подтверждения перед запуском нет.
- [Режим совместимости пишет в базу и сервис opencode, пока может работать и сам opencode] → Это поведение blackbird, пользователь включает его сам. Подсказка у флажка об этом говорит.
- [Два плагина с копией кода расходятся] → Принято осознанно (D1).
- [Структура архивов релиза blackbird неизвестна до первой загрузки] → `package_plugin.py` ищет бинарник по имени в любом каталоге архива и падает, если не нашёл.
